# Lightagent 0.5.0

**Prepared, not released.** This page is the release body for `v0.5.0`. A tag push drafts the GitHub release with generated notes; a manual run of the release workflow is a dry run unless `dry_run` is turned off on the tag. Paste this page above the generated notes before publishing.

0.5.0 makes the four specialist workers (researcher, coder, reviewer, tester) operational and bounded, makes research runs report how they really ended, budgets each model turn against the context window the model is actually served with, and hardens remote tool egress. It also ships the identity, provisioning and multi-user foundations, **all of them off and not activated**. The minor version reflects behavior changes that apply by default. They are listed first.

## Behavior changes that apply by default

| Change | What you notice | To keep the old behavior |
| --- | --- | --- |
| Workers share the lead's budget | All workers below one lead run share its turns, tool calls and time, at most `subagents.max_workers_per_run` (6) of them. Previously each worker got its own full limits. | Raise the lead profile's limits. |
| Role profiles are no longer cloned | A role (`researcher`, …) runs the typed built-in worker. Generated role profiles stay on disk and are superseded; customized ones keep working (`legacy_profile`). | `subagents.resolution = "legacy_profiles"` (operator runs only) |
| Depth and scope limits are exact | `max_depth = 2` no longer allows a third generation, and a `tool_scope` can no longer be widened by nested delegation. | None (this is a fix). |
| Research runs end truthfully | A stream without a finish signal ends as `Incomplete`; a token-limited answer as `MaxTokens` (it used to be `EndTurn`). After tools run, the last allowed turn answers without tools. | None (this is a fix). |
| SSE resumption | Run events carry ids. `GET /runs/{id}/events` resumes from `Last-Event-ID` or `?after=`, and the Web UI no longer duplicates the transcript on reconnect. | Clients that ignore ids are unaffected. |
| `rag.realtime` and embeddings are bounded | One 45 s deadline inside the tool's 60 s limit. Embedding requests time out (30 s; Infinity uses `platform.infinity.timeout_secs`). | None |
| Served context window | History is packed against the window Lightweight reports (`/v1/capabilities`, or the `/v1/models` row on older gateways) instead of `runtime.n_ctx` or 4096, which are now labelled fallbacks. A tool result that would crowd out the answer is shortened in what the model sees, and the run can end with the new `ContextLimit` stop reason. With nothing configured, no `max_tokens` or reasoning field is sent. | `generation.context_window` can narrow a reported window, never stretch it. |
| Length continuation | An answer cut off at its length limit gets one tool-less continuation turn, only when the window is known and has room and the run has a turn and time left. Still cut off afterwards, it ends `MaxTokens`. | `generation.continuations = 0` |
| HTTP MCP `auth` fails closed | A server whose configured `auth` cannot be used (unset variable, unreadable or empty file, unsendable header) is no longer contacted without it when that `auth` applies to the run; the run reports `mcp_auth_unusable`. | None (this is a fix). |
| Egress hardening | `web.fetch` vets every resolved address of every hop, including allow-listed hosts, and ignores proxy environment variables. Metadata and management endpoints are always refused. Userinfo URLs, HTTPS→HTTP redirects and loops are refused. HTTP MCP does not follow redirects. | Allow an internal host explicitly with `web.trusted_networks`. |
| Patch mutation re-checks | `patch.apply` and `repo.commit` re-check the run's authority and the proposing worker's assignment immediately before writing or moving the branch. | None |
| Jev and Lightweight `Auto` | Jev model routing never replaces `Auto`. `active` classification adds guidance only with `classification.workflow_guidance`. | None |

## New, opt-in

| Feature | Setting (default) | Notes |
| --- | --- | --- |
| Assign a role to your own private worker profile | `lightagent workers assign <role> --worker <profile>` | Ownership-checked and re-checked on every worker turn; a refusal never falls back |
| Coder patch workflow | built in; `repo.commit` needs `platform.github_actions.commit_refs` | `patch.propose` → `patch.apply` / `repo.commit` (fast-forward only, allowlisted branch), each with its own approval |
| Tester through GitHub Actions | `platform.github_actions` (absent) | Dispatches only allowlisted workflows, refs and inputs; nothing runs locally |
| Worker approvals | built in | A worker's pending action waits under a one-time handle: `agent.resume_worker` (always asks) or `agent.decline_worker` |
| Bounded repair after checks | `subagents.max_repair_rounds = 1` | With an active plan only: once checks have run, the coder may revise its change, and each check may re-run once on the new change, never twice on the same change. A check that cannot run reports the change as **unverified** |
| Jev specialist selection | `subagents.selection = "off"` | `shadow` records a plan; `active` applies it only to profiles in `selection_profiles`. Needs classification on. See `docs/subagents/specialist-selection.md`. |
| Provider-compatible tool names | `inference.tool_names = "native"` | `portable` for endpoints that require `^[a-zA-Z0-9_-]{1,64}$` (OpenAI's API and compatible validators) |
| Output ceilings and a run-wide output pool | `generation.max_output_tokens`, `generation.max_run_output_tokens` (unset) | The ceiling is sent as `max_tokens` and can only lower a turn's allowance. The pool bounds what the lead, its workers and continuations generate together and ends the run with `OutputBudget`; turns reserve a bounded amount, so concurrent workers are not starved. See `docs/architecture/generation-budget.md`. |
| Adaptive output allocation | `generation.adaptive_allocation = "off"` | `plan` or `jev`, and only with `max_run_output_tokens`: a lead reserve, a follow-up reserve and a share per planned role. See `docs/architecture/adaptive-allocation.md`. |
| Research for untrusted runs | `subagents.remote_research = false` | `agent.research` only: read-only, never generic delegation |
| Readiness | `lightagent workers status`, `GET /api/lightagent/v1/workers`, the Tools screen | Per role: ready, degraded, disabled, permission_denied or unavailable, with reasons |

## Migration

1. **Before upgrading:** no action is required. Existing configurations load unchanged.
2. **Role profiles:** generated clones are superseded; customized ones are reported as `legacy_profile`. Make the choice explicit with `lightagent workers assign <role> --worker <profile>` (keep yours) or `--builtin`.
3. **Budgets:** if long delegations now stop early, raise the lead profile's `max_turns`, `max_tool_calls` or wall clock. Workers draw from those.
4. **Egress:** an internal host that used to be reachable through `web.allow_domains` now also needs `web.trusted_networks` (operator-only).
5. **Jev routing:** run `lightagent config jev-routing-report` to see which profiles strict routing permission would deny. Nothing switches automatically.
6. **Rollback:**
   - `subagents.resolution = "legacy_profiles"` restores role profiles for operator runs;
   - `subagents.selection = "off"` and `inference.tool_names = "native"` are the defaults;
   - `subagents.max_repair_rounds = 0` turns repairs off;
   - downgrading to 0.4.1 leaves new files unused: `workers.json` per profile, and `identity/` and `credentials/` only if created.

## Restrictions in this release

- **No tenant execution sandbox.** In multi-user mode, untrusted users can get only the read-only researcher. Coder, reviewer and tester stay `permission_denied` (`requires_isolation`). The Linux bubblewrap backend remains experimental and unreachable from any request path.
- **Multi-user mode, provisioning, profile-scoped credentials and remote credentials are present but not activated.** Nothing in this release turns them on.
- **Website capability presets are not supported.** An operator applies `research@1` with `lightagent profile preset`. The Web protocol is unchanged, at exactly LA-WEB-PROVISIONING/1 r4.
- **Workers run one at a time** within a lead run.
- **No live model-competence or Jev selection-accuracy result** is claimed. Those evaluations are prepared and blocked pending authorization.
- **Packages:** macOS ARM64 (`aarch64-apple-darwin`), Windows x64 (`x86_64-pc-windows-msvc`) and Linux x64 (`x86_64-unknown-linux-gnu`). There is no Intel Mac (`x86_64-apple-darwin`) package. Nothing is code-signed; verify downloads against `SHA256SUMS`.

## Verification

Every build, lint, test, render and package step runs on GitHub-hosted runners:
- `check`: Linux, macOS, Windows, Web UI render, provisioning fixtures, package smoke, paired E2E, sandbox, revocation, Open Terminal, Qdrant and Infinity;
- `subagents`: seeded gaps, and the live tester broker against real GitHub Actions;
- `jev evaluation`.

- `release`: every package is built, smoke-tested and checksummed. A manual run is a dry run by default and creates no release.

They ran on every pull request in the stack. The release commit must pass them again before it is tagged; the dry-run evidence for this candidate is in `docs/releases/v0.5.0-dry-run.md`.
