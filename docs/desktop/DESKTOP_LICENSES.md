## 3. The obligations and how they are met

MPL-2.0 is file-level copyleft. For distribution in executable form
(§3.2): the Source Code Form must be made available and recipients told
how to obtain it, at no more than the cost of distribution; the
executable may be under other terms that do not limit the recipients'
rights in that source. Notices in the covered files must be kept (§3.4).
Larger Works may combine it with other code (§3.3).

| Obligation | Implementation | Verified by |
|---|---|---|
| Tell recipients the source is available, and where | THIRD_PARTY_NOTICES.txt has an MPL-2.0 section: each crate's version, crates.io page, archive URL and SHA-256 | generated per target; bundled; installed copy compared |
| Make the Source Code Form available | the exact archives are on crates.io; each release also attaches the same archives as `desktop-mpl-sources-<version>.tar.gz` (supply chain artifact `mpl-sources/` with SHA256SUMS and MPL-2.0.txt) | archive hashes equal Cargo.lock's |
| Include the license | each MPL crate's published LICENSE text is in the notices; selectors, published without one, is pointed to the identical MPL-2.0 text (cssparser 0.37.0's LICENSE), and `MPL-2.0.txt` is beside the archives | the gate fails if no MPL-2.0 text is available |
| Keep the covered files' notices | the files are not modified | checksum equality |

**Release step still to be done (needs release approval):** attach
`desktop-mpl-sources-<version>.tar.gz` (the `mpl-sources/` artifact of
the release's own run) to each Desktop release, as THIRD_PARTY_NOTICES.txt
says. Until that is done for a release, the notices' statement about
release attachments is not yet true for it.
