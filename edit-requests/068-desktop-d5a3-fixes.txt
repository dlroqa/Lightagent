D5a-3: no expect in the lock guard; wrap-up turns in the test providers

- `ExclusiveLock::into_file` returns an `Option` (clippy denies `expect`
  in library code; check run 41439783665).
- A wrap-up turn (continue `answer`, and a run that did not ask to pause)
  adds an instruction message after the tool result, so the last message
  is not the tool result. The hosted fake provider now attributes a request
  to the latest user message that carries a scenario marker, the continue
  check looks for the unread tool result anywhere after the prompt, and the
  separate-process test's provider answers once the conversation holds a
  tool result (desktop run 41439783419: answer and default were filed as
  unmarked requests).
