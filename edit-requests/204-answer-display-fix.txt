=== message
Show the final answer when a turn ends with a generation report

The cause, traced in the tests before this commit: once a model's window
is known (Lightweight reports it), the runtime budgets each turn and sends
`generation.report` before `turn.completed`. The Web UI's run-event hook
listened for a fixed list of names without it. A browser EventSource
drops a named event that has no listener, so the hook read the next id as
a gap and reconnected after the last id it held, and every replay began
with the same dropped event. The terminal event never arrived: the answer
stayed in the reasoning panel without its action row, and only a reload,
which reads the saved session, showed it. The same hook serves the browser
build and the Desktop's relay, so every target was affected.

The hook now listens for every name the API sends (`generation.report`,
and the catch-all `event`; scripts/check-event-names.py keeps the lists
equal). When a replay shows the same gap again, the missing ids are events
this client has no listener for, not lost ones, so the hook accepts the
next event instead of replaying forever. A lost event is still replayed
and kept, because the replay holds it.

- The Web UI and the Desktop show the final answer, and its action row,
  as soon as a run ends when each turn is budgeted, as it is whenever the
  model's window is known (Lightweight reports it). The runtime then sends

  every event the API sends, and no longer replays forever over an event
