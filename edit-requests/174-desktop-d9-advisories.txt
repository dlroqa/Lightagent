Clear the runtime's known vulnerabilities; read the AppImage launch for what it is

The supply-chain gate's first run (desktop run 41843537628) found 15
RustSec advisories in Cargo.lock, which the bundled runtime and the CLI
share (desktop/Cargo.lock: none; the UI's production npm packages: none):
rustls 0.23.43, rustls-webpki 0.103.15, webpki-root-certs 1.0.9,
ctutils 0.4.2, zstd 0.13.3, zstd-safe 7.2.4, zstd-sys 2.0.16, and four
for zip 8.6.0 (patched in 9.0.0). Each is updated on the runner to its
patched release (`=== update`); zip moves to 9.0.0. release-update only
reads one named entry of a release archive and never extracts, so the zip
advisories did not reach it, but the gate stays strict.

The AppImage launch passed every readiness check; it failed only the
orphan check, because the process run.py ends is the AppImage's own
wrapper, not the desktop host, so the host and its runtime rightly kept
running. The .deb launch shows the host's lifeline. For the AppImage the
fact is recorded instead of gated, and the account's processes are ended
after it.
