=== message
Keep the app mounted under the close question; settle the switch after its reload

The native runs at f84f308 (desktop run 41826163830) failed two checks on
all four targets:

- After "Keep working" the run's rest never appeared. The gate rendered
  the app directly when ready and inside a wrapper while asking about
  close, so the question's coming and going remounted the whole app and
  the conversation lost the run it was showing. The app now always sits
  in the same wrapper (display: contents), made inert and hidden only
  while the question shows.
- The switch's own reload ended the script that pressed Use while it
  waited to see a blocked switch, so the script never answered. The
  script now only presses Use; the harness waits for the host to serve
  the profile and only then looks for a blocked switch.

Also recorded, not gated yet: whether a run still working is shown again
after a plain reload of the page.
