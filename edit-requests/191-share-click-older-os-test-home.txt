Release candidate: Share by a real click, no macOS 14 image, a unique test home

- native.py share-focus: Share is pressed with a real mouse click
  (SendInput) on the button. The run on 6aa873c (desktop 42158154084)
  showed that a script click opens no share sheet: navigator.share needs
  user activation, which a script click does not give, so focus was never
  tested against the flyout.
- release.yml desktop-older-os: macos-14 removed. GitHub no longer runs it
  ("The configuration 'macos-14-arm64-us-default' is not supported", dry
  run 42155896523), so no hosted macOS image older than 15 exists; the
  macOS floors stay declarations, recorded in the acceptance record. The
  Windows Server 2022 run stays.
- desktop_serve.rs: each scratch home gets a per-process counter as well
  as the time. Both tests start at once, and macOS clocks tick in
  microseconds, so the time-based name could repeat; check (macos-x64) on
  6aa873c failed with the runtime exiting before its handshake. Test only,
  as the MCP test-directory fix was (#81).

fn scratch_home() -> std::path::PathBuf {
    // Unique per call: both tests start at once, and macOS clocks tick in
    // microseconds, so a name from the time alone can repeat.
    static NEXT: std::sync::atomic::AtomicU64 = std::sync::atomic::AtomicU64::new(0);
    let nanos = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .map(|elapsed| elapsed.as_nanos())
        .unwrap_or(0);
    let call = NEXT.fetch_add(1, std::sync::atomic::Ordering::Relaxed);
    std::env::temp_dir().join(format!(
        "lightagent-desktop-serve-{}-{nanos}-{call}",
        std::process::id()
    ))
}
