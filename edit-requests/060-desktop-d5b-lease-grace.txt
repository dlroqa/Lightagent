=== message
D5b: a lease being released is waited for briefly, a held one never

On Linux a released lease can still read as held for an instant: a
process that starts a child (fork or clone, then exec) gives the child
copies of its open files until the exec closes them, and an OS file lock
is released only when every copy is closed. The API test that regenerates
right after the previous run was recorded hit that window on Linux only
(check run 41405132318); macOS and Windows passed, and the new
separate-process tests passed on all four platforms.

`lease_run` now retries for up to 500 ms before reporting the session
busy. A turn that really holds the lease is still refused, after at most
that grace; nothing ever queues behind another process's turn.
