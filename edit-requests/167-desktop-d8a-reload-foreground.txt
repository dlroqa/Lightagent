Gate the reload check, say why a script failed, and try harder for the foreground on Windows

Desktop run 41831639407 passed every native check on all four targets.
From its records:

- A run still working through a page reload is shown again with its
  answer on every target: that is now a gated check.
- WebKit reports a failed script as a bare stack, so the reply now leads
  with the error's message.
- On Windows the OS key presses were sent but the window was never the
  foreground window. Before key presses the harness now tries the
  foreground the way Windows allows it (an ALT press, then
  SetForegroundWindow on the window titled Lightagent) and records
  whether it took.
- The narrow-window check opens the chat first, so it does not depend on
  the screen the previous scenario left.

# Windows gives the foreground only to a process that has had input: an ALT
# press first, then SetForegroundWindow on the app's window. It reports the
# window, the foreground window after, and whether they are the same.
WINDOWS_FOREGROUND = r'''
Add-Type @"
using System; using System.Runtime.InteropServices;
public static class Fg {
  [DllImport("user32.dll")] public static extern IntPtr FindWindow(string c, string t);
  [DllImport("user32.dll")] public static extern bool SetForegroundWindow(IntPtr h);
  [DllImport("user32.dll")] public static extern bool ShowWindow(IntPtr h, int n);
  [DllImport("user32.dll")] public static extern IntPtr GetForegroundWindow();
  [DllImport("user32.dll")] public static extern void keybd_event(byte vk, byte scan, uint flags, UIntPtr extra);
}
"@
$h = [Fg]::FindWindow($null, "Lightagent")
[Fg]::keybd_event(0x12, 0, 0, [UIntPtr]::Zero)
[Fg]::keybd_event(0x12, 0, 2, [UIntPtr]::Zero)
[Fg]::ShowWindow($h, 9) | Out-Null
$set = [Fg]::SetForegroundWindow($h)
Start-Sleep -Milliseconds 300
$now = [Fg]::GetForegroundWindow()
"window=$h set=$set foreground=$now same=$($now -eq $h)"
'''
FOREGROUND = []
