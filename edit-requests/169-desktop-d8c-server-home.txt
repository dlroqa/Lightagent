Give the remote server's home an active profile; pin HERMES_HOME's errors and precedence

Desktop run 41832537110 and check run 41832537170 at bfa1570: a plain
`lightagent serve` on a fresh home exits with "no active profile — run
`lightagent init` first" (remote-server.log in the run's artifact), so the
server-info test, remote.py and the native remote scenario never had a
server. The desktop runtime sets its own home up; a plain server's home is
now given a profile first, and the backend test starts the desktop
runtime before the keyed server.

HERMES_HOME (owner decision 2026-11-04: an explicitly empty value stays
invalid, not unset; document and test, no behavior change): the test now
also pins the empty value's error as it reads today, the CLI refusing it
too, a value naming a file refused like a missing folder, and a folder
given coming first past an unusable HERMES_HOME.
